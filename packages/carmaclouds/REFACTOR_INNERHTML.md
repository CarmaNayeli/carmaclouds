# Refactor: replace `innerHTML` templates with DOM construction

**Status:** Planned — not started. Scoping only.
**Goal:** Eliminate the ~165 `UNSAFE_VAR_ASSIGNMENT` (innerHTML) warnings from `web-ext lint`
by building UI with DOM APIs (`createElement` / `textContent`) instead of assigning
HTML-string template literals to `innerHTML`.

## Why

Every flagged site interpolates **DiceCloud character data** (`${spell.name}`,
descriptions, stats, notes) into an HTML string assigned to `innerHTML`. A character
sheet whose name/description contains `<img src=x onerror=…>` would execute script in
the extension/VTT context. Today this is a real (low-likelihood) XSS surface. It does
**not** block the unlisted/self-distributed signed build, but it would matter for a
public addons.mozilla.org listing (human review) and is the right thing to harden.

A full DOM rewrite (vs. a DOMPurify sanitizer) was chosen deliberately: no new runtime
dependency, and `textContent` makes injection structurally impossible rather than
filtered.

## Scope

- **~165 dynamic `innerHTML =` assignments** across **~37 source files**.
  (~25 additional `innerHTML = ''` clearing assignments are string literals, NOT
  flagged — leave them, or switch to `replaceChildren()` opportunistically.)
- Source of truth is `packages/carmaclouds/src/**`, `packages/carmaclouds/owlbear-extension/**`,
  and `packages/core/src/modules/**`. The `dist/`, `dist-chrome/`, and `website/public/`
  copies are generated by `build.js` — never edit those.

### The two hard problems (not just text substitution)

1. **Inline event handlers — 43 occurrences, 8 files.**
   33 are in `owlbear-extension/popover.js` alone (32 `onclick` + 1 `onsubmit`).
   These embed `onclick="… rollAbilityCheck('${label}', ${mod})"` strings that call
   global functions with interpolated args. Each must become an `addEventListener`
   wired to the created element, with the args captured in a closure (no more string
   interpolation of arguments — this also removes an injection vector).

2. **Hover styling via `onmouseover` / `onmouseout` — ~12 occurrences.**
   Used purely to swap inline styles on hover (spell-cards, dice-roller, popup-sheet,
   roll20, owlcloud adapter). Replace with a CSS class + `:hover` rule rather than JS
   handlers.

### File inventory by tier (rewrite order)

| Tier | Files | Why first/last |
|---|---|---|
| **1. Pilot** | `owlbear-extension/popover.js` (16 innerHTML, 33 handlers) | The surface you actually run; highest handler density — proves the pattern end-to-end |
| **2. Core modals** | `packages/core/src/modules/*` (spell-modals, feature-modals, hp-management, resource-manager, sheet-builder, action-display, etc.) | Shared, well-contained modal builders; loaded as global scripts |
| **3. Popup adapters** | `src/popup/adapters/{rollcloud,owlcloud,foundcloud,coyotecloud}/*` | esbuild-bundled; large files (owlcloud-popup ~10k lines, popup.js ~15k) |
| **4. Content scripts** | `src/content/{roll20,dicecloud,character-sheet-overlay}.js`, `src/popup-sheet.js` | Injected overlays; verify against live Roll20/DiceCloud DOM |
| **5. Foundry** | `foundry-module/scripts/foundcloud.js` (13) | Runs in Foundry, not flagged by web-ext (separate distribution) — lowest priority |

## Strategy

### A small DOM-builder helper (keeps rewrites readable)

Hand-written `createElement` chains for these large templates would be very verbose.
Introduce one tiny helper and express every rewrite through it:

```js
// h('div', { class: 'ability-box', style: '…', onClick: () => rollSave(label, mod) },
//    h('div', { class: 'ability-name', text: label }),
//    h('div', { class: 'ability-score', text: String(score) }))
function h(tag, props = {}, ...children) {
  const el = document.createElement(tag);
  for (const [k, v] of Object.entries(props)) {
    if (v == null) continue;
    if (k === 'text') el.textContent = v;               // safe text
    else if (k === 'html') el.appendChild(v);           // pre-built node only
    else if (k.startsWith('on') && typeof v === 'function')
      el.addEventListener(k.slice(2).toLowerCase(), v); // real listener
    else if (k === 'class') el.className = v;
    else el.setAttribute(k, v);                         // style/title/etc.
  }
  for (const c of children.flat()) {
    if (c == null) continue;
    el.append(c.nodeType ? c : document.createTextNode(String(c)));
  }
  return el;
}
```

### The dual module-system constraint

The helper must be usable from both loading models:
- **esbuild-bundled** files (content scripts, popup adapters) → `import { h } from '…'`.
- **global-script** modules (`packages/core/src/modules/*`, *"loaded as plain scripts,
  exported to globalThis"*) → `h` must also exist as a global.

Plan: define `h` once in a small module that both **exports** it (ESM) and assigns
`globalThis.h = h`, and ensure that file is loaded before the global-script modules in
every HTML entry point (`popover.html`, `popup.html`, `popup-sheet.html`, content-script
ordering in the manifests). Confirm load order in `build.js` / manifest `js` arrays.

## Concrete before/after (representative — popover ability box)

**Before** (`owlbear-extension/popover.js` ~2673):
```js
html += `
  <div class="ability-box ${isProficient ? 'save-proficient' : ''}">
    …
    <div … onclick="event.stopPropagation(); rollSavingThrow('${abilityLabel}', ${saveMod})" …>
      <div …>Save</div>
      <div …>${saveMod >= 0 ? '+' : ''}${saveMod}</div>
    </div>
  </div>`;
```

**After:**
```js
const box = h('div', { class: `ability-box ${isProficient ? 'save-proficient' : ''}` },
  h('div', { class: 'ability-row' },
    h('div', { class: 'ability-name', text: abilityLabel }),
    h('div', { class: 'ability-score', text: String(score) })),
  h('div', { class: 'ability-actions' },
    h('div', { class: 'ability-save', title: `Roll ${abilityLabel} save`,
               onClick: (e) => { e.stopPropagation(); rollSavingThrow(abilityLabel, saveMod); } },
      h('div', { class: 'label', text: 'Save' }),
      h('div', { class: 'val', text: `${saveMod >= 0 ? '+' : ''}${saveMod}` }))));
container.appendChild(box);
```
Note this also moves the inline styles to CSS classes (`.ability-row`, `.ability-actions`,
`.ability-save`) — a required side task wherever inline `style="…"` is heavy.

## Per-surface testing (no automated UI tests exist — manual)

- **Owlbear popover:** load extension, open a synced character, exercise every button
  (ability/save rolls, hit dice spend, short/long rest, spell/feature/action modals,
  inventory, chat). Compare against current behavior.
- **Popup adapters:** open the extension popup on each tab (RollCloud/OwlCloud/
  FoundCloud/CoyoteCloud) and render a character.
- **Content scripts:** verify overlays on live Roll20 and DiceCloud pages.
- After each tier: `npx web-ext lint --source-dir=dist` — `UNSAFE_VAR_ASSIGNMENT`
  count should monotonically drop toward 0.

## Risks & gotchas

- **Behavioral drift:** template rewrites can subtly change layout/spacing; inline-style
  → CSS-class moves are the most error-prone. Do one surface at a time and eyeball it.
- **Argument-passing handlers:** any handler that relied on interpolating a value into
  the onclick string must capture that value in a closure; watch for loop-variable
  capture (`let`, not `var`).
- **Global load order:** if `h` isn't defined before a global-script module runs, it
  throws. Verify manifest/script ordering up front (Tier 1 will surface this).
- **Big files:** `popup.js` (~15k lines) and `owlcloud-popup.js` (~10k lines) hold many
  sites — budget real review time, convert in sub-batches by function.
- **Foundry module** isn't covered by web-ext lint; deprioritize unless hardening for
  its own sake.

## Effort estimate

- Helper + load-order wiring: ~0.5 day.
- Tier 1 pilot (popover.js): ~1 day (handler-dense, validates the approach).
- Tiers 2–4: ~3–5 days depending on how much inline-style → CSS extraction is done.
- **Total: ~5–7 focused days**, best done as one PR per tier so each is reviewable and
  independently testable.

## Definition of done

- `web-ext lint --source-dir=dist`: `UNSAFE_VAR_ASSIGNMENT` at 0 (or only the deliberate
  helper-internal `appendChild` path, which is not flagged).
- No remaining inline `on*=` handlers or `onmouseover`/`onmouseout` style toggles in the
  converted surfaces.
- Manual smoke test of every converted surface passes.
